# 0.3.0 release evidence and limits

The bounded release criteria passed, including a fresh authenticated remote-cancellation/reconnect/role-refresh check. This document does not claim complete hosted Chat UI parity.

Reviewed Chat UI source: `1c9c9bcbd92da1c4bdcc7d4a20354191c747709e`. Tested integration: Pi 0.87.1 / Node 22.22.3, user-installed `pi-mcp-adapter@2.37.0` and direct authenticated HF `intern` tools. Other adapters and models may be compatible but are not certified here.

On a non-PRO personal HF account with Jobs credits, two two-step GPU smokes, one ten-step training job, and one two-step real-model Pi-agent submission **completed** using a small public model and dataset. Early/final Trackio 0.39.0 SQLite snapshots persisted in a private dataset; authenticated readback found loss rows, while unauthenticated requests to metrics and model artifacts returned HTTP 401. The trained private model reloaded for inference. A downloaded snapshot opened in a localhost-only Trackio dashboard with sharing disabled. All verification jobs were confirmed terminal. These tests were task-scoped, explicitly authorized, and are not run by unit tests or package installation.

**Monitoring deviation (D13):** creating a private hosted Trackio Gradio Space on the tested free account returned HTTP 402. No Space or bucket was created. The approved default is local Trackio within the Job, private dataset snapshots and Job-log monitoring while running, then a local dashboard after authenticated download. **No live hosted dashboard is promised without a subscription.** HF Jobs require a positive credit balance; provider quotas, not this extension, enforce spending limits.

Initial 0.3.0 validation passed **30 repository tests** plus **118 optional tests regenerated from the pinned upstream GitHub source** (148 at verification time), TypeScript and diff checks. Pre-publication guard fixes and the release review added seven offline regressions (37 repository tests now pass): adapter-error submission recovery, optional-tool activation, expired creation receipts, direct-control-only authorization, exact sandbox token grammar/tool scope, structured child lifecycle reconciliation, and cancellation/termination state handling. A fresh checkout's `npm test` runs only the reproducible repository tests; `npm run test:upstream` requires first regenerating the Git-ignored tests from the exact source SHA. Coverage includes registered extension handlers, real Pi SDK delegates, privacy/billing guards, prompt fidelity and resume. The final tarball was installed into an isolated npm prefix: Pi advertised `--ml-intern`, restored a disk-backed ML-mode session after a model reply, and the packaged metrics helper executed with explicit repository arguments. The tarball scan found no personal resource identifiers, billing amounts, credentials, session files or disposable training scripts.

A subsequent user-authorized lifecycle check used `pi-mcp-adapter@2.37.0` and deterministic zero-cost scripted inference to create exactly one disposable T4-small sleep job with a ten-minute timeout. Pi retained its reference while the first session shut down without implicit cancellation. A reopened saved session forced `/mcp reconnect hf-intern`, restored ML mode and tools, and ran a role-restricted `check_job` child against the live job. The parent then issued an explicit Jobs cancellation and a second isolated check confirmed the terminal cancelled state. A malformed pre-dispatch attempt was rejected by adapter argument serialization; a fresh `ps` confirmed its unique name had created no resource before the successful run. The remote resource ID, account and billing details remain only in the ignored local verification record. The timeout bounded worst-case T4 runtime far below the separately authorized €3 allowance; exact provider settlement is not claimed.

This is evidence for the **bounded tested path**, not for arbitrary model quality, unrestricted agent decisions, every user's eligibility, automatic monitoring while Pi is closed, transport-request abort behavior, or other adapters. Existing destinations with unverified visibility are not reused for writes. Remote jobs are not cancelled on exit; the validation cancellation was a separate explicit action. Preserve the upstream source/adaptation mapping in [`../upstream/README.md`](../upstream/README.md).

Detailed job identifiers, private artifact locations and billing notes are deliberately kept in a **local, unshipped verification record**; this release does not publish those private resource names.

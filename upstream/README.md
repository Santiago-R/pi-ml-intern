# Source and adaptation manifest

Source: Hugging Face [`chat-ui`](https://github.com/huggingface/chat-ui/tree/1c9c9bcbd92da1c4bdcc7d4a20354191c747709e), Apache-2.0, commit **`1c9c9bcbd92da1c4bdcc7d4a20354191c747709e`**, 2026-09-26, “stamp ml intern runs with prompt version (#2645)”. See the accompanying [LICENSE](LICENSE). The earlier proposal reviewed `80f4eda`; this implementation rechecked upstream and reviewed its new virtual-file, service-event and registry prompt branches. No runtime source downloads.

The immutable linked Git commit is the verbatim source reference; this repository does **not** duplicate the raw Chat UI tree. `scripts/sync-upstream.mjs` refuses any checkout at a different SHA and generates only files used by this port. `prompts/` contains executable prompt modules with imports replaced by their original constant values/local modules. `builtins.json` extracts definitions and doctrine without loading Chat UI's web services. `github/` preserves the runtime implementation; the upstream specs/fixtures are regenerated from the pinned SHA when requested and Git-ignored here. Its config import uses local `GITHUB_TOKEN`, and a literal NUL in a cache-key string is spelled `\0` for reviewable source. No general prompt shortening or deduplication.

Regenerate from exactly that checkout:

```sh
node scripts/sync-upstream.mjs /path/to/chat-ui
```

Semantic changes live in `runtime/`, not hidden edits to the snapshot. The 0.3.0 release is a **bounded Pi adaptation**, not a claim of complete Chat UI parity.

## Evidence and bounded limitations

- Authenticated adapter discovery, identity, public model lookup, Jobs `ps`, and filesystem `stat`; credential-free, adapter-normalized core schemas in `tests/fixtures/hf-intern-tools.json` (account-specific description redacted).
- Authenticated `check_job` SDK child using the real adapter and **scripted, free model responses**: Jobs `ps` succeeded; a nonexistent-job `inspect` produced an error visible through the adapter's actual error hooks. Parent/child extension shutdown completed. This tests plumbing, not model task quality.
- Offline tests exercise real registered handlers and real SDK loops, role refusal, iteration stop/repetition, provider/reasoning inheritance, failed partial summaries, cancellation, mode entry/exit/resume, file expansion, private defaults, and headless decisions.
- **Live D13 evidence:** private dataset/model creation through authenticated MCP, two direct T4-small smoke Jobs, one ten-step Job and a scoped real-model Pi-agent two-step Job completed on a non-PRO personal account. Early/final Trackio SQLite snapshots contained loss rows, anonymous reads were denied (401), the private model reloaded for inference, and a localhost-only Trackio dashboard opened after authenticated download. Jobs were funded under explicit task-scoped authorization. Public-safe results: [release evidence](../docs/release-evidence.md). Private resource IDs and billing notes are not shipped. The final two-step test exercised real-model paid submission and job monitoring with a deterministic script; it does not establish unbounded agent quality or a hosted live dashboard.
- **Known gaps / bounded validation:** hosted private Trackio requires PRO on the tested account; D13 explicitly changes the default rather than pretending live dashboard parity. Existing-destination visibility, automatic sandbox-file import/version history, in-flight MCP transport-request aborts and unconstrained agent quality remain open product limits. Offline tests cover cancellation state reconciliation and in-process delegate aborts. A separately authorized authenticated disposable run persisted a live job across shutdown, forced adapter reconnect, refreshed an isolated `check_job` role, explicitly cancelled the job and confirmed its terminal state. Other adapters have source-inspection evidence only.

Do not describe scripted Jobs as unbounded agent reliability or hosted Chat UI parity. The funded D13 path and a constrained real-model Pi-agent submission passed; 0.3.0 retains the documented live-lifecycle and hosted-dashboard limitations. Keep private verification artifacts for user review.
